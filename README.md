# apt-deps-graph

Инструмент визуализации графа зависимостей пакетов Ubuntu (apt).
Реализован на Python 3.10+ без сторонних библиотек для получения
зависимостей.

## Сбор данных (этап 2)

Репозиторием считается URL каталога с индексом пакетов Ubuntu или прямой
URL файла `Packages`, `Packages.gz` или `Packages.xz`. Если указан
каталог, к нему добавляется `/Packages.gz`. Индекс скачивается модулем
`urllib` и разбирается вручную (`src/apt_repo.py`): из каждого описания
берутся поля `Package`, `Version`, `Pre-Depends`, `Depends`, `Provides`.
Из зависимостей удаляются ограничения версий, архитектуры и фильтры сборки.
Альтернативы (`a | b`) сохраняются как группа.

Нужен полный индекс пакетов выпуска, например
`http://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64`. Индексы
`noble-updates` и `noble-security` содержат только обновлённые пакеты, и
зависимости неизменённых пакетов в них не находятся (такие вершины остаются
листьями). Пакеты из `universe` лежат в отдельном индексе.

Если указана `--version`, выбирается запись с точно такой версией, иначе
первая запись пакета.

## Параметры командной строки

| Опция | Описание |
|-------|----------|
| `-p`, `--package` | имя анализируемого пакета (обязательно) |
| `-r`, `--repo` | URL репозитория или путь к файлу тестового репозитория (обязательно) |
| `-t`, `--test-mode` | режим работы с тестовым репозиторием |
| `-v`, `--version` | версия пакета |
| `-o`, `--output` | имя файла с изображением графа (`graph.png` по умолчанию) |
| `--order` | вывести порядок загрузки зависимостей |
| `--tree` | вывести зависимости в виде ASCII-дерева |

## Построение графа (этап 3)

Граф строится от пакета `--package` обходом в ширину, реализованным
рекурсивно по уровням (`src/graph.py`, `build_graph`): функция обрабатывает
текущий уровень и вызывает себя для следующего. Вершина раскрывается один
раз, поэтому транзитивные зависимости собираются без повторов, а циклические
зависимости (в том числе самозависимость) не приводят к зацикливанию.
Рёбра, замыкающие циклы, находятся отдельным итеративным обходом в глубину
и выводятся списком.

В реальном репозитории для каждой группы альтернатив (`a | b`) выбирается
первая альтернатива, присутствующая в индексе (или поставляемая через
`Provides`); если ни одной нет в индексе, вершина остаётся листом. Версия
`--version` относится только к анализируемому пакету.

### Тестовый режим (`--test-mode`)

`--repo` указывает на текстовый файл, где строка `A: B C` означает, что
пакет `A` зависит от `B` и `C`. Имена пакетов состоят из больших латинских
букв, строки с `#` и пустые игнорируются. Примеры лежат в `tests/data/`.

```
make run ARGS="-p A -r tests/data/inner_cycle.txt -t"
```

```
Граф зависимостей A (BFS с рекурсией):
  A -> B
  B -> C, E
  C -> D
  E -> E
  D -> B
Вершин: 5, рёбер: 6
Обнаружены циклические зависимости (замыкающие рёбра):
  D -> B
  E -> E
```

## Порядок загрузки (этап 4)

Режим `--order` выводит порядок, в котором пакеты нужно загрузить, чтобы
зависимости оказывались раньше зависимых пакетов. Порядок строится обходом
графа в глубину (постпорядок, `dfs_postorder` в `src/graph.py`): пакет
добавляется в список после всех своих зависимостей, анализируемый пакет
идёт последним. Каждый пакет встречается один раз; при циклических
зависимостях цикл разрывается на замыкающем ребре, и эти рёбра выводятся.

```
make run ARGS="-p A -r tests/data/large.txt -t --order"
```

```
Порядок загрузки зависимостей A:
  1. H
  2. E
  3. I
  4. F
  5. B
  6. G
  7. C
  8. D
  9. A
```

### Сравнение с `apt`

Сравнение выполнено на Ubuntu 24.04 (noble): наш порядок для индекса
`noble/main` против вывода `apt-get -s install --no-install-recommends
<пакет>` (строки `Inst`).

| Пакет | В нашем порядке | Установил бы apt | Порядок общих пакетов |
|-------|-----------------|------------------|-----------------------|
| apache2 | 73 | 8 | совпадает |
| postgresql-client-16 | 49 | 3 | совпадает |
| ruby3.2 | 28 | 11 | отличается |

Все пакеты, которые установил бы `apt`, есть и в нашем списке. Различия:

1. Наш список содержит все транзитивные зависимости, а `apt` пропускает
   пакеты, уже установленные в системе (например, `libc6`, `dpkg`), поэтому
   его список короче. Для `apache2` и `postgresql-client-16` порядок общих
   пакетов совпал.
2. Для `ruby3.2` порядок отличается. Пакеты `ruby3.2`, `libruby3.2`,
   `ruby`, `ruby-rubygems`, `ruby-sdbm`, `libruby` зависят друг от друга по
   кругу, поэтому строгий порядок «зависимости раньше» для них невозможен.
   Мы разрываем цикл на рёбрах, найденных обходом в глубину, а `apt` и `dpkg`
   выбирают собственный порядок настройки. Оба порядка допустимы.
   Дополнительно `apt` учитывает установленные пакеты, версии и
   `Conflicts`/`Breaks`, а мы нет.

### Порядок на тестовых репозиториях

| Файл | Случай | Команда (`-t --order`) |
|------|--------|------------------------|
| `tests/data/chain.txt` | цепочка A→B→C→D | `-p A -r tests/data/chain.txt` |
| `tests/data/diamond.txt` | ромб, общая зависимость D | `-p A -r tests/data/diamond.txt` |
| `tests/data/cycle.txt` | цикл A→B→C→A | `-p A -r tests/data/cycle.txt` |
| `tests/data/inner_cycle.txt` | цикл внутри графа и самозависимость | `-p A -r tests/data/inner_cycle.txt` |
| `tests/data/large.txt` | несколько путей к одним пакетам | `-p A -r tests/data/large.txt` |
| `tests/data/isolated.txt` | пакет без зависимостей | `-p A -r tests/data/isolated.txt` |

Ромб (`D` загружается один раз и раньше `B` и `C`):

```
Порядок загрузки зависимостей A:
  1. D
  2. B
  3. C
  4. A
```

Цикл (разрывается на ребре `C -> A`):

```
Порядок загрузки зависимостей A:
  1. C
  2. B
  3. A
Циклы разорваны на рёбрах: C -> A
```

## Визуализация (этап 5)

Граф записывается в текстовый файл на языке [D2](https://d2lang.com)
(рядом с изображением, с расширением `.d2`), затем утилита `d2`
превращает его в PNG (`src/render.py`). Вершины — пакеты, рёбра — прямые
зависимости, направление слева направо.

Установка `d2`: `curl -fsSL https://d2lang.com/install.sh | sh -s --`
(Linux/macOS) или `winget install terrastruct.d2` (Windows). При первом
построении PNG `d2` скачивает браузерный движок Playwright, нужен доступ в
интернет.

```
make run ARGS="-p bash -r http://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64 --tree -o bash.png"
```

Фрагмент `bash.d2`:

```
direction: right
"bash" -> "libc6"
"bash" -> "libtinfo6"
"bash" -> "base-files"
"bash" -> "debianutils"
"libc6" -> "libgcc-s1"
```

Опция `--tree` печатает ASCII-дерево. Уже раскрытые вершины помечаются
`(см. выше)`, вершины, замыкающие цикл, — `(цикл)`:

```
bash
├── libc6
│   └── libgcc-s1
│       ├── gcc-14-base
│       └── libc6 (цикл)
├── libtinfo6
│   └── libc6 (см. выше)
├── base-files
...
```

### Примеры для трёх пакетов

Индекс `noble/main`, команда вида
`python3 -m src.main -p <пакет> -r http://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64 --tree -o <пакет>.png`.

| Пакет | Вершин | Рёбер | Циклы |
|-------|--------|-------|-------|
| bash | 14 | 25 | `libgcc-s1 -> libc6` |
| python3 | 34 | 66 | `libgcc-s1 -> libc6` |
| curl | 32 | 81 | `libgcc-s1 -> libc6` |

Файлы `*.png`, `*.svg` и `*.d2` игнорируются git, чтобы в репозиторий не
попадали результаты работы.

### Сравнение со штатным инструментом

Штатный инструмент для apt: `apt-cache depends --recurse --no-recommends
--no-suggests --no-conflicts --no-breaks --no-replaces --no-enhances <пакет>`.
Сравнивались множества вершин и рёбер (только `Depends` и `Pre-Depends`).

| Пакет | Вершин у нас / у apt-cache | Рёбер у нас / у apt-cache | Вершины только у apt-cache |
|-------|----------------------------|---------------------------|----------------------------|
| bash | 14 / 16 | 25 / 26 | `mawk`, `original-awk` |
| python3 | 34 / 39 | 66 / 78 | `cdebconf`, `libslang2`, `libnewt0.52`, `libtextwrap1`, `libdebian-installer4` |
| curl | 32 / 32 | 81 / 78 | нет |
| apache2 | 73 / 81 | 199 / 220 | `libaprutil1-dbd-mysql`, `-odbc`, `-pgsql`, `libpq5`, `libmysqlclient21`, `libodbc2`, `libltdl7`, `mysql-common` |

Вершин, которые есть у нас и нет у `apt-cache`, нет. Причины расхождений:

1. **Альтернативы.** `apt-cache` показывает все варианты `a | b`, а мы берём
   первую подходящую альтернативу. Пакет `apache2-bin` зависит от
   `libaprutil1-dbd-sqlite3 | ...-mysql | ...-odbc | ...-pgsql`: мы берём
   `sqlite3`, а `apt-cache` добавляет остальные три вместе с их зависимостями
   (`libpq5`, `libmysqlclient21`, ...).
2. **Виртуальные пакеты.** `tzdata` требует `debconf | debconf-2.0`, а
   `debconf-2.0` предоставляют и `debconf`, и `cdebconf`. Мы выбираем
   `debconf` (он есть в индексе), `apt-cache` показывает обоих поставщиков,
   отсюда `cdebconf` и его зависимости в `python3`. Так же для `bash`:
   `base-files` требует виртуальный `awk`, его предоставляют `gawk`, `mawk`
   и `original-awk`, а мы берём `gawk`.
3. **Запись виртуальных зависимостей.** `apt-cache` выводит `perl:any`,
   `libgnutls30` и т. п. как отдельные виртуальные вершины, под которыми
   перечислены поставщики; мы сразу заменяем их реальным пакетом. Поэтому в
   сравнении у нас «лишние» рёбра `apache2 -> perl`, `librtmp1 -> libgnutls30t64`:
   это те же зависимости, записанные без промежуточной вершины.
4. **Версии.** Мы читаем индекс одного выпуска (`noble/main`), а `apt-cache`
   использует версию-кандидат из всех включённых источников (обновления,
   безопасность), поэтому возможны мелкие отличия в зависимостях
   обновлённых пакетов.

## Обработка ошибок

Все параметры проверяются до начала работы; при ошибке выводится
сообщение `Ошибка: ...` и код возврата 2 (неверное имя пакета, URL без
`http(s)://`, отсутствующий тестовый файл, неверная версия, расширение
файла изображения не `.png`, несуществующий каталог).
